## Architecture Snapshot

- The crate has no third-party dependencies and one external boundary: launching the `codex` CLI as a subprocess.
- [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:48) owns the CLI surface, argument parsing, audit prompt construction, target path resolution, report persistence, and top-level user messaging.
- [codex.rs](/C:/dev/rust_agent/crates/app/src/codex.rs:101) owns request modeling plus process concerns: executable discovery, git-repo detection, command construction, temp-file capture, and subprocess execution.
- Tests are inline and mostly protect parser behavior plus argument assembly; there is no integration-style protection around executable discovery, environment probing, or end-to-end audit/report flows.

## Key Findings

### [High] Codex executable discovery is brittle and tied to specific install layouts

- Evidence: [codex.rs](/C:/dev/rust_agent/crates/app/src/codex.rs:216) `resolve_codex_executable` only accepts candidates where `is_file()` is true; [codex.rs](/C:/dev/rust_agent/crates/app/src/codex.rs:227) seeds bare names like `codex.exe` and `codex.cmd`, which will not resolve via `PATH` under this check.
- Risk: the app can fail even when Codex is correctly installed, unless it happens to live in the current directory, `CODEX_CLI_PATH`, a specific VS Code extension path, or a specific npm path. That makes the core behavior fragile and platform evolution expensive.
- Refactor direction: keep explicit override paths, but let bare `codex` names resolve through normal process lookup or a dedicated `where`/`which` probe. Add tests that isolate `CODEX_CLI_PATH`, `USERPROFILE`, and fallback resolution order.

### [Medium] `main.rs` is an overloaded switchboard with several distinct reasons to change

- Evidence: [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:56) and [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:118) parse two command surfaces manually; [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:244) runs the audit workflow; [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:276) authors the audit prompt; [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:298) resolves target paths; [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:331) persists reports.
- Risk: small changes to CLI syntax, audit policy, filesystem behavior, or output formatting all land in one file. That raises change coupling and makes future subcommands likely to expand the same central module.
- Refactor direction: extract a minimal `audit` module around `AuditCommand`, prompt generation, target validation, and report saving. Keep the top-level `main` focused on dispatch and exit behavior.

### [Medium] The process API hides mode-specific behavior behind one `RunResult` shape

- Evidence: [codex.rs](/C:/dev/rust_agent/crates/app/src/codex.rs:93) exposes one `RunResult`, but [codex.rs](/C:/dev/rust_agent/crates/app/src/codex.rs:106) returns empty `stdout`/`stderr` in interactive mode, and [codex.rs](/C:/dev/rust_agent/crates/app/src/codex.rs:165) does the same for verbose exec mode while only non-verbose exec captures output.
- Risk: callers must know undocumented invariants about when `final_message`, `stdout`, and `stderr` are meaningful. That is a mild interface-shape/LSP problem: the type suggests uniform availability, but actual semantics vary by mode.
- Refactor direction: split execution into explicit APIs such as `run_interactive` and `run_exec`, or return an enum whose variants encode what data is actually available.

### [Medium] Test coverage stops before the volatile environment and filesystem boundaries

- Evidence: passing tests cover parsing and pure helpers in [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:345) and [codex.rs](/C:/dev/rust_agent/crates/app/src/codex.rs:282), but not `resolve_codex_executable`, `is_inside_git_repository`, `run_exec`, `save_audit_report`, or `run_audit`.
- Risk: the least stable parts of the program are the least protected. Refactoring subprocess discovery or audit persistence will rely on manual testing, which is error-prone across machines and install layouts.
- Refactor direction: add boundary-focused tests with temp directories and controlled environment variables; if needed, introduce very small seam functions for current-dir, temp-dir, and executable lookup rather than a large abstraction layer.

## Principle Review (SOLID / DRY / KISS / YAGNI)

- `SOLID`: the main tension is single responsibility. [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:1) mixes CLI parsing, audit policy, path handling, persistence, and presentation. Interface shape is also weaker than it looks because `RunResult` means different things in different modes.
- `DRY`: duplication between `parse_run_args` and `parse_audit_args` is currently acceptable. The repeated logic is still readable, and forcing a generic parser now would likely add indirection without enough payoff.
- `KISS`: the overall crate is refreshingly small and concrete. The main violation is executable discovery, where manual path probing is more complex and less reliable than delegating to standard command resolution.
- `YAGNI`: the code shows good restraint. There are no speculative traits, repositories, or plugin layers. The next step should be cohesion-oriented extraction, not framework-style abstraction.

## Refactoring Roadmap

1. **Stabilize**
   - Fix executable resolution so normal `PATH` installs work reliably.
   - Add tests for executable lookup, non-git behavior, verbose vs non-verbose exec, and audit report persistence.
   - Make failure reporting and file naming safer before deeper structural changes.

2. **Simplify**
   - Move audit-specific behavior out of `main.rs` into a small concrete module.
   - Replace the single ambiguous `RunResult` contract with mode-specific outcomes or functions.
   - Keep concrete types; avoid introducing traits unless a second execution backend or caller actually appears.

3. **Reshape**
   - If the tool grows beyond two commands or adds cross-platform support, split the binary into small library modules such as `cli`, `audit`, and `codex_runner`.
   - Normalize dependency direction so top-level command dispatch depends on focused helpers, not the reverse.

## Quick Wins

- [codex.rs](/C:/dev/rust_agent/crates/app/src/codex.rs:216): replace `is_file()`-based discovery for bare command names with real command lookup.
- [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:331): use a collision-resistant filename strategy for audit reports; second-based names can overwrite same-second runs.
- [main.rs](/C:/dev/rust_agent/crates/app/src/main.rs:211): preserve both `stdout` and `stderr` on failure instead of dropping `stdout` whenever `stderr` is non-empty.
- [codex.rs](/C:/dev/rust_agent/crates/app/src/codex.rs:207): use a more collision-resistant temp capture filename if concurrent execs are possible.
