- Priority: High

- Rationale: the resolver bug sits at an OS/process boundary; changing it without tests risks replacing one machine-specific failure with another.
- Target files/modules: `crates/app/src/codex.rs`
- Dependencies: none
- Implementation outline:
  1. Introduce small private helpers that separate pure decision logic from direct environment reads, especially candidate classification and parent-walk git detection.
  2. Add unit tests for override precedence (`CODEX_CLI_PATH` first), USERPROFILE-derived candidates, acceptance of bare command names as lookup targets, and parent-directory `.git` detection from nested temp directories.
  3. Keep the helpers local to `codex.rs`; do not introduce traits or a mockable process layer just for this phase.
- Tests to add or update: resolver precedence tests, bare-name acceptance tests, git-root walk tests
- Verification commands: `cargo test -p app`
- Acceptance criteria:
  - Resolver behavior is specified by tests before the bug fix lands.
  - Git-probe behavior is covered without requiring this workspace to become a Git repo.
- Rollback/fallback notes: if helper extraction starts leaking abstractions across modules, keep them private and test via narrower pure functions.
- Notes for implementation agent: the goal is targeted seams, not an architecture rewrite.

#### P1-T2: Fix Codex executable resolution to honor normal PATH installs

- Priority: High
- Source finding: `Codex executable discovery is brittle`
- Rationale: this is the highest-severity user-facing failure mode because the tool can report Codex as missing when it is actually installed correctly.
- Target files/modules: `crates/app/src/codex.rs`
- Dependencies: `P1-T1`, `G2`
- Implementation outline:
  1. Distinguish explicit filesystem candidates from bare command-name candidates in the resolver path.
  2. Preserve existing precedence for explicit overrides and known install locations, but stop rejecting bare `codex` / `codex.exe` / `codex.cmd` names just because they are not files relative to the current directory.
  3. Keep `configure_child_path` behavior intact so VS Code tool dirs still lead PATH where intended.
- Tests to add or update: PATH fallback regression tests from `P1-T1`; not-found message test if practical
- Verification commands: `cargo test -p app`
- Acceptance criteria:
  - A PATH-only Codex install is no longer blocked by `is_file()` gating.
  - Explicit `CODEX_CLI_PATH` and explicit filesystem candidates still win over PATH lookup.
- Rollback/fallback notes: if a dedicated PATH probe becomes too platform-specific, prefer allowing bare names through to `Command::new` and defer deeper heuristic changes.
- Notes for implementation agent: do not broaden this into a full installer-discovery framework.

#### P2-T1: Replace the ambiguous `RunResult` contract with explicit execution outcomes

- Priority: Medium
- Source finding: `RunResult hides mode-specific behavior behind one shape`
- Rationale: empty-string and `None` sentinel fields make callers responsible for undocumented invariants; that slows future work and makes behavior harder to reason about.
- Target files/modules: `crates/app/src/codex.rs`, `crates/app/src/main.rs`
- Dependencies: `P1-T2`, `G1`
- Implementation outline:
  1. Replace the single always-partial `RunResult` with either split APIs or explicit result variants. Recommended default: separate interactive and exec-oriented result types/functions.
  2. Update `run_request`, `run_audit`, and `run_plan` so they consume only the fields that are guaranteed by the chosen API.
  3. Remove meaning-by-convention cases where empty `stdout`/`stderr` or absent `final_message` mean different things by mode.
- Tests to add or update: compile-path caller tests and execution-result semantics tests
- Verification commands: `cargo test -p app`
- Acceptance criteria:
  - Callers no longer rely on undocumented mode-specific `RunResult` semantics.
  - The new API makes final-message availability and output capture rules explicit.
- Rollback/fallback notes: if an enum variant design causes too much churn, split the public entry points first and keep shared internals private.
- Notes for implementation agent: choose the smallest explicit contract that fixes the ambiguity; do not add traits or backends.
